Modular Django monolith, PostgreSQL. 13 apps:

| App | What it owns | Owner |
|---|---|---|

| `employees` | `Employee` (permanent id), `EmployeeAssignment` (dated placement + reusable employee code), `EmployeeCompensation` (dated salary) | Ajay |
| `scheduling` | shifts, department shifts, employee's own shift, weekly offs, holidays (+ year calendar), attendance settings, `WorkCalendar` | Ajay |
| `leaves` | leave types, leave requests/segments, `LeaveDay` | Ajay |
| `attendance` | `AttendanceRecord`, sessions, punch allocations, pairing, day window, live recalculation, calendar, "Now" badge | **Nihal** |
| `devices` | device catalogue, `BiometricDevice`, enrollments, punches, ADMS endpoints (`/iclock/…`), server-address change, user sync, "Which devices count" | **Nihal** |
| `payroll` | salary settings (versioned rules), penalty rules, overtime decisions, salary runs, payslip | Ajay |
| `auditlog` | append-only audit (`record_company_event`, field `after_data`) | shared |
| `access_control`, `subscriptions` | permissions / plan features (partly built) | — |
| `base_template` | no models: base layout, sidebars, topbar, shared CSS/JS, templatetags, the **employee panel** (`me_views.py`, `/me/`) | Ajay |

**Rules every change follows:**

- **Tenancy:** every company-owned model inherits `common.models.TenantOwned`
  (adds `company`; its manager **raises** if queried without a company context).
  Code runs queries inside `with use_company(company_id):`; `Model.all_objects`
  is for platform-level/ingestion code only. `TenantMiddleware` sets
  `request.company_id`. Never weaken the manager, never give root/superuser a
  membership as a shortcut.
- **Writes go through service functions** (`<app>/services.py` etc.): permission
  check (`require_structure_manager` = owner/company admin), `use_company`,
  `create_validated`/`full_clean`, and an audit row in the same transaction.
  Views and forms call services; forms re-validate nothing the service trusts.
- **Dated/versioned data:** placement, salary, shifts, salary rules
  (`PayrollPolicyVersion`), penalty rules are effective-dated; a change from a
  later date keeps history; the same start date corrects. Salary rules and
  penalty rules start on the 1st of a month; a finalised (posted) salary month
  is locked for attendance and overtime.
- **Physical table names** always set with `Meta.db_table`; leave/attendance/
  payroll tables use the `payroll_` prefix (MODEL_FIELD_DICTIONARY.md).
- **`SelfServiceGate`** (common/middleware.py, after TenantMiddleware): an
  Employee or Branch-manager login may only open `/me/…` (+ login/logout/switch
  company); company pages redirect to My account, form posts get 403.
- **Attendance is live**: no Calculate button. `attendance.services.recalculate`
  runs on punch arrival and when pages read closed days (`refresh`). Days inside a
  posted salary run are never rewritten.
- Future APIs: **FastAPI** around the same services (not DRF), when needed.

Main URLs: `/` dashboard · `/employees/` · `/organization/…` (branches,
departments, Edit employee) · `/shifts/` (overview, shifts, weekly offs,
holidays, holiday calendar, attendance settings) · `/leave/` · `/attendance/`
(list, `calendar/`) · `/salary/` (month, `settings/`, `overtime/`, payslips) ·
`/devices/` (devices, enrollments, punches, messages, unresolved,
`attendance-rules/`) · `/me/` (employee panel) · `/platform/` (root) · `/admin/`.

  Also: `.form-page`, `.stack`, `.row`, `.grid.grid--2`, `.toolbar`,

  Cancel.

  (include `leaves/includes/field.html` renders one). Checkboxes:
  `<label class="check">{{ field }}<span>label</span></label>` inside `.field`.

  (`CompanyDateTimeWidget` / `_date()` widgets); times use a text box with
  `data-timepicker` (`common.forms.time_widget()`), never `type="date|time"`.

  (`js-select`) for fixed choices.

  `data-label-when="field:value=Label|…"` (`dependent.js`). `[hidden]` always
  hides (base.css).
- **Derived values are never typed** (a shift's length and "ends next day" come
  from its times).
- Static files are cache-busted (`?v=hash` in dev) — no Ctrl+F5 needed.
- Templates: 4-space indentation, one tag per line as in existing files. Check

## 6. Every decision that is final (don't re-ask)

**Attendance** (DEVICE_ATTENDANCE_POLICY.md step 7):
- Check-in / break-out / break-in / check-out are decided by the software by
  pairing the day's scans; device keys ignored. Final — **don't mention pairing
  limitations to Ajay.**
- A day closes at the next shift start or 24 h after its start, whichever comes
  first. A trailing OUT stays a break-out until the day closes, then it is the
  check-out. A day ending on an IN is checked out at the shift end and flagged
  for review (no setting).
- Arriving early is not overtime and not paid; worked time counts from the shift
  start. Real-time attendance, no Calculate button.
- Scanning back in after the shift and never scanning out = an open overtime
  session: blank check-out, in review, unpaid until someone sets when they left.

**Overtime** (A9, done):
- Counts from the shift end (the shift's "Overtime after (minutes)" stays 0).
  Example Ajay confirmed: end 18:00, check-out 19:15 → 75 min counted → 1 hour
  paid under 1-hour blocks.
- **Approved automatically when the day ends in a real scan**; only a session
  nobody scanned out of (or a check-out set by rule) waits for admin/HR.
  Overtime under the company's minimum shows "Too short to pay" and never waits.
- Pay = hours × hourly rate × multiplier: overtime **2×**, work on a day off
  **2×** (both on Salary settings). Hourly rate: hourly staff their rate; daily
  staff rate ÷ shift paid hours; monthly staff one day's pay ÷ shift paid hours.
  "Don't pay overtime shorter than (minutes)" and "Pay overtime in blocks of"
  (every minute/15/30/60) per day.
- Approvers: owner, company admin, **HR**.

**Salary / leave / shifts:**
- Keep the **Monthly** pay basis (Ajay once asked to drop it — he misunderstood).
- Commas on every amount shown. Dependent fields only when relevant.
- Leave requests are approved by the **branch manager** (`manager` role +
  `allowed_branches`); fallback to company admin when there is none or the
  requester is the manager is a proposal, not yet confirmed.
- Employees see **finalised payslips only**; finalising a month is A11.
- Remove the **"Paid day off" / "Paid holiday"** checkboxes (days off always
  paid; daily/hourly pay on days off stays on Salary settings) — A5c.
- Night shift is derived from the times (end earlier than start); "The break is
  paid" shows only when break > 0.
- Rotating shifts **deferred** ("initially I want to keep it simple").
- Data tables: mandatory rule, but scheduled **later** (A15, after A8).

**Working style Ajay expects:**
- Build without asking permission repeatedly; ask only real decisions (with a
  recommendation). He dislikes pointless manual steps — prefer automation.
- Each build reply: **what's done so far / this turn / what's left / docs &
  plan updated / any `.env.example` change with variable and value** — and the
  **navigation path** (sidebar → page → button) for every new page.
- Only say something is on his screen after it is actually in his folder.
- **Testing:** while building, only the affected apps' tests. The **full suite
  once before pushing main** for merges and big steps (in the background;
  `python manage.py test --parallel 4 --keepdb`, ~6 min, ~890 tests). Small
  contained changes: the affected apps' tests are enough (Ajay agreed). After a
  **new migration**, run the full suite **without** `--keepdb`
  (`--parallel 4 --noinput`) — stale per-worker databases otherwise fail with
  "cannot pickle 'traceback' object" (tblib is not installed, so a parallel
  failure hides its traceback: rerun that app serially to see it). Never run the
  full suite just because main was pulled.
- Don't reset the dev database; don't enter passwords in a browser; Ajay runs
  `migrate`.
