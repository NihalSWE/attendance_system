## What this project is
A multi-tenant SaaS that turns ZKTeco fingerprint/face-device punches into
attendance, leave and payroll for multiple companies. Django 6.1 + PostgreSQL
(psycopg 3), django-environ for config, tzdata for per-company timezones.
No DRF and no Celery: the device protocol is plain text, and attendance
recalculates live (synchronously) for only the affected employee-days.

## How to get the latest code
origin = https://github.com/ajay016/attendance_system.git (main = merged final).
1. `git status` — if there is uncommitted local work, STOP and review it first.
2. `git fetch origin`
3. `git checkout main`
4. `git pull --ff-only origin main`  (fast-forward; if it refuses, STOP and
   reconcile deliberately — do not force).
5. Migrate with the project's venv Python (not system python):
   `python manage.py migrate`
6. Restart the dev server and confirm the login page loads.
Nihal's merged branches (feature/n10-*, feature/n11-*, feature/login-logo) can
be ignored or deleted.

  Lead's area (employees).
- **Getting them onto the devices without one-by-one entry.** The safe,
  model-agnostic approach is "enrol at the device, then auto-map device users to
  employees in the software": reading a device's user table already works on
  every ZKTeco model, while pushing/writing users is fragile per-model and must
  be measured on real hardware first (a wrong delete key once wiped every user
  on the 2A). Biometric templates (face/finger) can never be pushed from
  software — they are captured at the terminal. Device-user mapping is Nihal's
  area; the employee CSV import is the lead's.
